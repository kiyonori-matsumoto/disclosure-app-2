# 想定ユースケースと情報設計（IA）

本ドキュメントは、適時開示・EDINET Notifier アプリにおける想定ユースケースと優先度、およびそれに基づく情報設計（UI/UX設計基準）をまとめたものです。

---

## 1. 想定ユースケースと優先度一覧

```text
【最優先（Tier 1）: リアルタイム速報 & フォロー通知】
  ├── UC-1: 保有・注目銘柄の適時開示をプッシュ通知で最速キャッチする（最重要）
  ├── UC-2: 今日の市場全体の開示タイムライン（TDNET / EDINET）を流し読みする
  ├── UC-3: 気になる企業を検索してフォロー（通知登録）する
  └── UC-4: 開示のタイトルからワンタップで原文PDF / EDINET書類を開く

【準優先（Tier 2）: タイムラインのノイズ削減 & 銘柄深掘り】
  ├── UC-5: タイムライン上で「お気に入りのみ」「特定タグ」に瞬時に絞り込む
  ├── UC-6: 会社の過去の開示一覧や次回決算日をまとめて確認する
  └── UC-7: あとで読むために気になる開示を保存（ブックマーク）する

【低頻度（Tier 3）: 定期チェック & アカウント・通知メンテナンス】
  ├── UC-8: 直近（本日〜数日内）の決算発表予定企業を一覧で確認する
  ├── UC-9: フォロー銘柄や通知タグの整理・解除を行う
  └── UC-10: 表示設定（定例・軽微な開示の非表示）やダークモードの設定
```

---

## 2. 各ユースケースの詳細

### 最優先（Tier 1: コア体験・高頻度）
> **アプリの存在価値そのもの。ここの体験が損なわれるとアプリを使う理由が失われます。**

| ID | ユースケース | ユーザーの行動・心理 | UI/UX上の要件 |
| :--- | :--- | :--- | :--- |
| **UC-1** | **フォロー企業の通知受信** | 「保有株に悪材料や上方修正が出たら仕事中でもすぐ気づきたい」 | ・バックグラウンドプッシュ通知の確実性<br>・通知タップで直接その会社の開示へ遷移できること |
| **UC-2** | **タイムラインの流し読み** | 「昼休みや引け後（15:00〜16:30）に、今日どんな開示が出たかザッと把握したい」 | ・画面縦幅を最大化し、邪魔な常駐バーを置かない<br>・TDNET / EDINET を1タップでサッと切り替えられる<br>・タイトルが読みやすく視認性が高い |
| **UC-3** | **企業の即座なフォロー** | 「ニュースで気になった銘柄を見つけたので、とりあえず通知が来るように登録しておきたい」 | ・開示一覧からドロワーを経由せず、右上の「🔍」から即検索できる<br>・検索結果からワンタップで⭐（フォロー）できる |
| **UC-4** | **開示原文（PDF）の即時閲覧** | 「タイトルだけじゃわからないから、中身の数字や資料をすぐ確認したい」 | ・リストタップで即ダウンロード＆PDFビューア起動<br>・ダウンロード中であることが分かるフィードバック |

---

### 準優先（Tier 2: 閲覧中のアクション・中頻度）
> **タイムライン閲覧をより便利にし、投資判断を支援する体験です。**

| ID | ユースケース | ユーザーの行動・心理 | UI/UX上の要件 |
| :--- | :--- | :--- | :--- |
| **UC-5** | **お気に入り・タグでの絞り込み** | 「全件だと開示が多すぎるので、自分の登録企業（または決算短信など）だけ見たい」 | ・タイムライン直下のチップから1タップで瞬時に切り替えられる |
| **UC-6** | **特定企業の開示履歴チェック** | 「この会社、前回の四半期決算や直近でどんな開示を出してたっけ？」 | ・開示一覧の企業名をタップして会社詳細画面へジャンプ<br>・過去の開示が時系列で並び、次回の決算予定も上部に表示される |
| **UC-7** | **開示情報の保存（クリップ）** | 「通勤中に見つけたこの開示、夜に家でじっくり分析したい」 | ・リスト項目の長押しやメニューから簡単に「保存」できる<br>・保存済み一覧から後でサッと見返せる |

---

### 低頻度（Tier 3: 補助機能・低頻度）
> **月に数回〜たまにしか使わない機能。ドロワーや設定画面に格納しておくのが適切です。**

| ID | ユースケース | ユーザーの行動・心理 | UI/UX上の要件 |
| :--- | :--- | :--- | :--- |
| **UC-8** | **決算予定カレンダーの確認** | 「今日・明日はどの会社が決算発表するのか見ておきたい」 | ・決算発表シーズン（5月、8月、11月、2月）にたまに見に来る程度なので、常駐ボトムバーではなくドロワー内に配置 |
| **UC-9** | **フォロー銘柄の棚卸し** | 「株を売却したから通知を解除したい」 | ・お気に入り一覧からスワイプで簡単に削除できる |
| **UC-10** | **表示・通知のノイズ削減設定** | 「投資信託や日々の定例開示が多くて邪魔だから非表示にしたい」 | ・設定画面から「日々の開示情報を表示しない」やテーマ設定ができる |

## 3. 情報設計（IA）の原則

1. **画面の主役は 9 割以上「タイムライン」**
   - 下部に常駐するボトムナビゲーションバーは縦方向のコンテンツ表示領域を奪うため採用しない。
   - スクロールで隠れるスマートな AppBar（`pinned: false, floating: true, snap: true`）により、読書領域を最大化する。
2. **「会社検索（🔍）」を最前面（AppBar 右上）に配置**
   - 「開示を見ていて気になった企業を即検索し、星マークでフォロー（通知登録）する」という最重要アクションをワンタップで行えるようにする。
   - 以前配置されていた更新されていない静的HPリンクは撤去し、ドロワーおよび設定画面内に「サポートサイト」として退避。
3. **TDNET と EDINET は 1 タップで切り替え可能な TabBar**
   - 2タップ必要なドロップダウンを廃止し、AppBar 内の直感的な下線付きタブで瞬時に切り替え可能とする。
4. **「お気に入り」は別タブではなく「タイムラインのフィルター（絞り込み）」を主動線とする**
   - タイムライン直下のチップで「お気に入りのみ表示」を切り替える体験を基本とし、管理用のお気に入り一覧はドロワーからアクセスする。
